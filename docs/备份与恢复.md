# 数据资产备份与恢复（P2-33）

## 数据资产清单

| 资产 | 位置 | 是否可重算 | 说明 |
| --- | --- | --- | --- |
| DuckDB 数据库 | `$FIL_DATA_DIR/market.duckdb` | 部分 | 行情、`pe_panel`、`div_panel`、指数池、同步历史；历史净值与累计面板难以回补，必须备份 |
| 审计日志 | `$FIL_DATA_DIR/audit.jsonl*` | 否 | 操作审计，不可重建 |
| 结果缓存 | `$FIL_DATA_DIR/webcache/*.pkl` | 是 | 可重算，备份后恢复可立即命中，缩短冷启动 |
| 状态文件 | `$FIL_DATA_DIR/*.meta.json` | 部分 | 兼容旧版本的元数据侧车 |

`$FIL_DATA_DIR` 默认 `output/data`；`FIL_ENV=dev` 时为 `output/dev/data`，
生产环境建议用 `FIL_DATA_DIR` 指向独立磁盘目录。

## 备份

```bash
python -m market_research.ops.backup backup --dest D:/backups/fil/2026-11-06
```

- 备份目录必须为空（脚本不会覆盖已有备份）。
- 一致性：脚本在 `storage.connection()` 持有的 DuckDB 文件锁内执行
  `EXPORT DATABASE ... (FORMAT PARQUET)`，获得停写快照；随后复制审计与缓存。
- 产物：`datasets.parquet`、`prices.parquet`、`schema.sql`、`load.sql`、
  `manifest.json`，以及 `audit.jsonl*` 与 `webcache/`。
- `manifest.json` 记录数据集数量、价格行数、数据集 revision 哈希、
  环境与创建时间，用于恢复后校验。

建议节奏：每日一次（RPO ≤ 24h）；重大同步后追加一次。数据库与审计体积
较小时可整目录保留最近 7 份，异地再存 1 份。

## 校验（恢复前）

```bash
python -m market_research.ops.backup verify --src D:/backups/fil/2026-11-06
```

- `problems` 非空 → 备份损坏或被改动，脚本拒绝恢复。
- `warnings` 只提示关键数据集缺失或审计缺失，不阻断恢复。

## 恢复

```bash
# 建议先停止 API / worker，避免恢复期间有任务持有数据库
python -m market_research.ops.backup restore --src D:/backups/fil/2026-11-06 --confirm
```

恢复流程在同一把文件锁内：清空 `datasets` / `prices` → `IMPORT DATABASE` →
复制审计与缓存 → 用 manifest 比对数据集 revision 哈希与价格行数。
任一项不一致即报错退出（不会静默留下半恢复状态）。

## 恢复后一致性检查

1. 脚本内建检查：`restore` 返回的 `live.n_datasets` / `n_price_rows` /
   `revision_hash` 必须与 manifest 相同。
2. 服务侧检查：`GET /api/ready`（依赖可用性）与 `GET /api/health`。
3. 数据抽查：运行一次最小真实数据冒烟（见 `scripts/smoke_real.py`），
   确认抓取→面板→分析→报告主链路可用。
4. 审计连续性：确认 `audit.jsonl` 可按行解析，恢复点之前的记录仍在。

RTO 参考：单机环境整库恢复为分钟级（取决于数据库体积与磁盘）；具体目标
由部署方按业务需要设定，脚本只保证「可执行、可校验」。
