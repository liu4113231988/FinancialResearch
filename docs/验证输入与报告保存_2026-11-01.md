# 验证输入与报告保存 · 2026-11-01

版本12补齐离线验证的输入与保存边界。先用回归复现了计算期间目标文件被创建仍遭覆盖、坏日期未在读取入口拒绝的问题，再修复共享读取和报告发布流程。

## 输入契约

- 清单需为JSON对象，`assets` 为非空数组且每项为对象；显式 `csv`、`benchmark_csv`、`calendar_csv` 必须是非空字符串，不能以错误类型或空路径静默退回缓存。
- 快照和验证CLI都接受UTF-8及UTF-8 BOM清单。无效JSON、清单结构和文件读取错误作为CLI错误退出，保留说明，不创建成功报告。
- CSV日期按ISO8601解析。CSV与缓存均需有效、唯一、升序、无时区的日线日期，不含日内时间或NaT；不自动排序或去重。
- 请求窗口内的OHLC及已有 `volume/amount/turnover` 转为数值。复用现有 `clean_bars` 检查OHLC完整、有限、为正及高低价关系；已有可选量价字段的负值、无穷或坏数值被拒绝。
- 可选字段缺失或NaN仍允许；不补零、不转换成交量单位。权限、涨跌停等额外列保留，原缓存对象不被修改。实际成交字段继续由原执行模块校验。

同一读取入口供验证资产、基准和快照准备使用。坏日线作为该资产的 `unavailable` 原因保存，其余资产继续评估，预定分母仍保留。数据校验发生在指标及训练之前；固定CSV错误不会被悄悄替换为网络数据。

## 不覆盖发布

已有目标文件时，CLI在评估前快速拒绝。评估结束后仍使用不可覆盖发布，解决“开始时不存在，计算期间被另一轮创建”的竞争窗口：

1. 先完成严格JSON序列化，拒绝非有限数值。
2. 在目标目录创建本轮专有临时文件，写完并关闭。
3. Windows使用拒绝替换目标的原子重命名；其他平台用不覆盖的硬链接发布。
4. 目标已存在或发布失败时返回CLI错误，保留已有目标；最后清理本轮临时文件。

不会用覆盖替换作为失败回退。非Windows发布要求文件系统支持同目录硬链接，不支持时明确失败。该分支本轮未在非Windows环境实测。这里的“不覆盖”是工具的写入契约，不是对外部程序设置只读权限。

报告目录创建、序列化或发布错误不会显示成功提示；已存在的报告和本轮计算期间出现的其他运行结果均保持原内容。新输出路径和既有 `--manifest/--output` 参数保持不变。
