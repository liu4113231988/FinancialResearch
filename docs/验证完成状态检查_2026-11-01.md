# 离线验证完成状态检查 · 2026-11-01

版本11修复完成状态误报。旧版只要任意留出对比有样本，就可能将整项证券标为 `evaluated`；缺失周期、候选或开发阶段没有参与完成判定。校准列表为空时，`all()` 还可能返回真。规则模式也只检查留出阶段是否有策略结果。

## 当前判定

| 模式 | 每证券预定项目 | 完成条件 |
| --- | --- | --- |
| 常规方向 | 2周期×2阶段×4候选，共16项 | 每个周期/阶段/候选恰好一条，成熟配对至少20个且 `ok=true` |
| 附加校准 | 2周期×5特征版本，共10项 | 每项恰好一条、校准器为 `fitted`，留出配对至少20个且 `ok=true` |
| 规则成交 | 2阶段×2策略×3费用，共12情景 | 每个阶段/策略/费率滑点恰好一条，至少2个估值会话 |

样本门槛沿用既有方向比较规则，不改变模型、时间划分、概率阈值、费用或统计量。零成交、资金买不起一手或亏损仍是有效账户结果，不要求盈利或成交数大于0。会话足够也不代表闭合交易足够，收益区间仍单独按原门槛判断。

每个资产的 `coverage` 保存预定数、达标数和 `incomplete` 明细；明细注明阶段、周期/策略、候选/费用、样本数和原因。顶层 `coverage` 汇总计数，`unit` 区分配对比较与费用情景。缺数据资产仍占完整预定分母，原始错误保留。

常规方向和规则模式全部达标时，资产为 `evaluated`、报告 `complete=true`；部分达标为 `partial`，全部未达标为 `insufficient`，读取或计算错误保持 `unavailable`。附加校准使用独立的 `calibration_coverage` 与 `calibration_complete`，不被空列表或重复候选绕过。原始数值和不完整项目仍保留在报告中。

CLI现在显示“预定评估完整”和“满足样本门槛：达标/预定”。`complete=false` 或配置校准后 `calibration_complete=false` 都返回2，报告仍落盘。这是版本11的状态语义变更；依赖旧版任意样本即完成的脚本，应改为读取覆盖明细。

完成仅表示预定项目满足计算/样本门槛，不证明显著性、校准有效或可交易获利。
