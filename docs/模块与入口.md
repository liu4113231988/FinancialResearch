## 数据与模型边界

- data.http：线程级超时、全进程限流、指数退避重试和基础序列清洗。
- data.provenance：供应商契约镜像（`CONTRACTS`）与抓取溯源滚动快照。
- data.quality：统一数据质量（ok/partial/degraded/failed、stale、缺失资产、溯源）。
- data.providers：基金净值、指数及估值数据源；字段缺失抛 `ProviderContractError`。
- data.providers.calendar：带版本、指纹和覆盖校验的供应商日历。
- market.execution：可分割账户、固定概率阈值及事后平均仓位匹配诊断。
- market.capital：离线不复权股票资金、整手、最低佣金和上一会话容量账户。
- market.uncertainty：固定配对路径的块自助诊断；仅常规离线模型验证启用，页面不增加重采样计算。
- market.targets：方向训练、成熟比较、证据和校准共享的目标/会话时钟；缺失报价不填补，无日历保留有效日线口径。
- market.context.percentile：窗口内有限观测的经验分位；当日缺失不输出，保留至少60个有限观测的门槛。
- research.market_snapshot / market_validation：独立快照与固定清单验证；资金配置可用于规则模式 `--execution-only` 和常规冻结留出模型对比，仅允许明确不复权股票报价。
- research.market_validation 的覆盖检查逐项核对预定阶段、周期、候选及费用；报告保存不完整明细，CLI据实际覆盖返回状态。
- research.market_validation 的共享日线读取校验资产/基准日期与价格；报告序列化后通过同目录临时文件不可覆盖发布。
- research.market_validation.check_calendar_coverage：快照及验证共用的日历边界、报价日期与末会话检查；基准同样核验。
- research.calibration：可选时间隔离的固定logit概率校准，支持常规离线验证，记录校准失败和原概率/校准概率配对结果。
- data.cache：缓存版本、元信息、旧 CSV 导入和 DuckDB 写入。
- data.panels：缓存数据集加载、基金/指数对齐和分析窗口。
- data.storage：DuckDB 事务、文件锁、数据指纹与统计。
- modeling.catalog：模型规格、默认参数和界面目录。
- modeling.estimators：单窗口拟合器、约束求解与股票仓位估计。
- modeling.engine：滚动样本外评估、进程池和模型报告。
- data.marketdata / modeling.models：稳定导入门面；具体实现已分离。
- serialization：股票、基金和任务结果共用的有限数值 JSON 转换。
- security：可选令牌认证、`Identity`（subject/tenant/scopes）与请求上下文。
- disclosure：免责与数据来源披露文案、作用域和位置；Web/报告/`/api/disclosure` 同源。
- audit：JSONL 操作审计（analysis.run / report.publish / data.write，5MB×5 轮转与脱敏）。
- funds.analysis：结果 `meta.data_basis/data_quality/provenance`、`result_completeness` 与回测可用性过滤。
- predictions：实盘最新收盘的预测台账（`prediction_records`）、到期结算与命中率/Brier 汇总；口径见[预测台账与回验](预测台账与回验.md)。
- ops.backup / ops.smoke：备份恢复与真实数据冒烟；入口见上表。

## 路径与兼容

`FIL_HOME` / `FIL_DATA_DIR` 决定运行目录，模块移动不会更改现有行情库与队列。静态文件位于 api/static，从 API 包资源定位，SQL 从 data/migrations 定位，不依赖当前目录推算。

`compat/src/` 与 `compat/webapp/` 集中实现 `src.*` 和 `webapp.*` 兼容转发，指向同一模块对象，避免配置/任务单例重复初始化；旧 pickle 中的类路径仍可解析。源码根目录只保留两个包搜索桥接文件，实际转发不再散落在根目录。兼容模块随 wheel 打包，新代码禁止依赖旧路径。4 个根目录入口与 10 个归档脚本用于源码工作区兼容，安装包提供命令入口。

Windows 每日任务名为 `MarketResearch-DailySync`，调用 `.venv/Scripts/pythonw.exe -m market_research.tasks.sync --once --time 18:30`。安装脚本成功注册新任务后，只清理属于当前工作区的旧任务注册。

验证重点：所有旧入口 --help、无副作用导入、旧类路径解析、独立 worker、多进程模型池、SQL/静态资源打包，以及从工作区外使用安装包。

测试按 api、data、funds、market、tasks、architecture、regression、integration、frontend、browser、tools 归类，数据库测试与 HTTP 测试分开；所有 Python 测试子目录含初始化文件，unittest 可递归发现。


## 根目录使用方式

```powershell
uv run python run.py --help
uv run python run.py analyze 110022
uv run python run.py experiments --window-years 2
uv run python run.py holdings --help
uv run python run.py 110022  # 兼容旧的默认基金分析
```

也可使用 `uv run market-research-cli ...` 或 `uv run python -m market_research.cli ...`。旧文件路径不再保留在根目录，例如原 `run_experiments.py` 改用 `run.py experiments`；需要归档脚本时可运行 `uv run python compat/entrypoints/run_experiments.py ...`。注册表是命令名、实现模块、说明和旧文件名的唯一映射来源。
