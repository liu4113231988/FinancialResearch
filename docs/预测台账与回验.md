# 预测台账与回验

核对日期：2026-11-08（同日口径修正）。本文记录实盘预测的落盘、结算与汇总口径；实现见 `src/market_research/predictions/`。本次修正把规则买卖事件与方向预测在记录和统计上彻底分开，并统一了平盘、周期时钟与净值口径。

## 一、记录范围

只记录**实盘最新收盘**的预测，历史区间回看、回测和离线研究不写入：

| 来源 | 操作 | 记录内容 |
| --- | --- | --- |
| 方向概率 | `analyze`（基金）、`market`（股票/指数） | 5/20 日 `probability`，方向按 `>=0.5` 记 up；`params` 冻结完整阈值（0.5 / 0.6 / 0.4）与 `horizon_basis` |
| 规则事件 | `backtest`（基金健康分）、`market`（股票/指数买卖点） | 仅在信号日等于最新收盘时记 **1 条**状态事件（`horizon=0`，无固定方向周期） |

- 规则买卖条件是"条件首次满足"的状态事件，基金健康分是拟合可信度风控，两者**都不是市场方向预测**，不再被拆成 5/20 日方向记录。
- 信号日与当前日期相差超过 `LIVE_MAX_LAG_DAYS=14` 自然日时跳过；请求参数中任一显式 `end` / `window_end` 早于今天时，整次分析不记账（历史回看时结果已可见）。
- 同一资产、同一收盘、同一来源、同一周期只保留首条（`id` 由这四项哈希生成）；重复分析不会重复记账，也不会用后一次结果覆盖已结算标签。
- 特征快照在信号日冻结：趋势分、最新指标、市场环境、规则原因、模型评估与训练行数等；方向记录另冻结 `horizon_basis` 与 `price_basis`，结算按同一时钟、同一净值口径取数。

## 二、记录字段

`prediction_records`（DuckDB，迁移 `data/migrations/004_predictions.sql`）主要字段：

- 身份：`id`、`created_at`、`as_of`、`asset_kind`、`asset_code`、`asset_name`
- 预测：`source`（direction/rule）、`direction`（up/down）、`horizon`、`probability`、`rule_score`、`rule_action`
- 当时状态：`features`（JSON 特征快照）、`regime`（strong/weak/mixed/unknown）、`price_basis`
- 可追溯：`model_version`（git commit + 版本）、`params`、`data_stamp`
- 判定：`status`、`target_date`、`judge_date`、`label`、`realized_return`、`judged_at`、`reason`

## 三、结算口径

- 判定期：方向记录按 5 / 20 周期判定；规则事件按固定 `RULE_EVAL_SESSIONS=5` 个会话记录触发后收益。到期后允许 2 个交易日宽限。
- 周期时钟：`horizon_basis=observed_bars` 按实际报价日推进，`calendar_sessions` 按供应商日历推进，与训练时一致；不再对全部资产统一按日历结算。
- 正确性：纯方向，`close(判定日) / close(信号日) - 1 > 0` 为上涨；up 且上涨、down 且下跌记 `correct`。`|return| <= 1e-9` 记 `neutral`（平盘对两个方向都不判对错），避免 down 方向白拿一次命中。不设幅度阈值，不做相对基准。
- 规则事件：结算标签为 `observed`，只保留 `realized_return` 用于事后归因，不判定方向对错。
- 基金取数：按记录中的 `price_basis`（`total` / 降级 `cum`）读取净值，不再统一换成 `total`。
- 股票/指数：目标会话缺失超过宽限期记 `blocked`（`missing_session`）；判定日一字板记 `blocked`（`limit_one_price`）；成交量为 0 记 `blocked`（`zero_volume`）。
- 基金：净值缺失超过宽限期记 `insufficient`（`净值缺失超过宽限期`），不判错。
- `neutral` / `observed` / `blocked` / `insufficient` 均保留 `realized_return` 供归因，但不计入方向命中率分母；`summary` 另给 `rule_events`、`rule_return_mean`、`rule_return_positive_rate`。

## 四、命令

```powershell
uv run market-research-cli predictions settle --limit 500
uv run market-research-cli predictions settle --today 2026-11-20 --fetch
uv run market-research-cli predictions summary
uv run market-research-cli predictions summary --group-by regime
uv run market-research-cli predictions migrate            # 预览，不写库
uv run market-research-cli predictions migrate --apply   # 实际迁移（建议先备份）
```

- `settle`：默认只读本地缓存；缓存未覆盖时记 `insufficient`。加 `--fetch` 才允许联网补数据。
- `summary`：输出总体与分桶的 `correct/incorrect/neutral/observed/blocked/insufficient`、`hit_rate`（仅方向预测）、`brier`、`legacy_rows`、`current_total` 及规则事件归因；`--group-by` 支持 `source`、`horizon`、`asset_kind`、`regime`。
- `migrate`：把口径修正前的规则行（同资产、同收盘、同动作，5/20 各一条）合并为一条 `horizon=0` 的状态事件，已结算记录改标 `observed` 并保留 `realized_return`。默认 dry-run 只报告 `legacy_rows` / `groups` / `would_delete`；`--apply` 才写库并删除同组重复行，幂等重跑返回 `deleted=0`。会删除数据，执行前请备份 `market.duckdb`。

## 五、Web 汇总与内置结算

- 只读接口 `GET /api/predictions/summary`（`/api/v1` 同路径，公开前缀）；`?group_by=` 支持与 CLI 相同的四组分桶，非法值返回 400。响应是 `ledger.summary()` 加 `ok=true`，不写数据库、不触发联网。
- Web 顶栏「预测回验」面板：显示 `current_total`、方向命中率、Brier、规则事件、待结算与旧口径行，支持分桶表格、手动刷新，并在底部展示口径说明「命中率只衡量方向，不构成有效性证明」。
- `tasks/worker.py::supervise` 每轮调用 `_advance_settle`：默认每 60 分钟在独立子进程执行 `predictions settle`，不占任务名额、不阻塞领取；子进程异常或启动失败只记日志；`--once` 不触发。
  - `FIL_PREDICTION_SETTLE_ENABLED=0` 关闭；`FIL_PREDICTION_SETTLE_MINUTES` 调整间隔（分钟，下限 1，配置错误回退 60）。
- CLI `predictions settle` 仍可手动触发；外部计划任务与内置调度二选一，避免重复结算（结算幂等，但重复会增加 DuckDB 写锁争用）。
- 离线 HTML 报告新增「10 预测台账回验」章节：CLI 在生成报告时只读 `ledger.summary()` 并塞入 `extra_meta["predictions"]`，读取失败（含 DuckDB 锁忙）只显示占位说明，不阻断发布。报告明确标注台账与回测使用不同样本与口径，不可互相印证；`build_report` 本身仍是纯函数。

## 六、已知边界

- 内置结算按固定间隔运行，不是交易日收盘事件驱动；跨时区或休市日仍会空跑一次幂等扫描。
- 基金规则信号的市场环境统一记 `unknown`；基金净值的历史版本/分红修订需结合 `data_stamp` 判断。
- 台账不自动回填历史预测：上线前的分析不会被追溯记录，避免事后拟合。
- 口径修正前已落库的旧规则行可用 `predictions migrate` 迁移；迁移行沿用原 `id`，`params.migrated_from` 标记来源。未迁移时 `summary` 仍单列 `legacy_rows` / `current_total`，方向命中率不受污染。
- 命中率只衡量方向，不衡量可执行收益：页面概率未单独校准，缺独立未来样本验证，交易成本、滑点、整手与申赎确认均未计入台账。
