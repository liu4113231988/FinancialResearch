# 运行环境与配置

产品口径：当前以**单用户**部署为主，但配置按 dev / local / prod 三档区分，
并为多用户/对外 API 预留了开关。默认值全部保持原有本地行为。

## 环境分档

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `FIL_ENV` | `local` | `dev` / `local` / `prod`；未知值回退 `local` |
| `FIL_DATA_DIR` | local/prod: `output/data`；dev: `output/dev/data` | 数据资产目录（DuckDB、审计、缓存） |
| `FIL_FIG_DIR` | local/prod: `output/figures`；dev: `output/dev/figures` | 图表产物 |
| `FIL_RES_DIR` | local/prod: `output/results`；dev: `output/dev/results` | 报告与冒烟结果 |

生产环境建议显式设置 `FIL_DATA_DIR` 到独立磁盘卷；`local` 保持仓库内路径，
不改变现有 CLI / Web 用法。

## 访问控制（P2-24）

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `FIL_ACCESS_CONTROL` | `off` | `off` = 单用户无认证；`token` = 校验 API 令牌 |
| `FIL_API_TOKENS` | 空 | `token` 模式下允许的令牌，逗号分隔；支持 `租户:令牌` |

- `token` 模式下，业务接口需带 `Authorization: Bearer <token>` 或 `X-API-Key`；
  未授权返回 401。
- `/`、`/api/health`、`/api/ready`、`/api/disclosure` 与静态资源保持公开，
  便于探针与页面加载。
- 启动日志会打印当前模式（单用户 / 令牌模式）。
- 多用户升级还需：把任务与结果缓存按 `Identity.tenant` 分区、按用户配额，
  以及用户的注册/登录体系；当前只预留了身份上下文与开关，不会强制登录。

## 数据抓取（P2-29）

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `FIL_HTTP_MAX_RPS` | `8` | 全进程抓取请求上限（请求/秒）；`<=0` 关闭限流 |
| `FIL_HTTP_TIMEOUT` | `30` | 单次抓取超时秒数，线程级生效；`0` 表示不限制 |
| `FIL_DATA_STALE_DAYS` | `10` | 数据末日超过该天数标记 stale |
| `FIL_NAV_DEGRADED_POLICY` | `reject` | 总回报口径失败时 `reject` 或 `allow_cum`（后者必须显式标注） |

重试为最多 4 次、指数退避（基准 1.2 秒 + 抖动）；`ValueError`/`KeyError`/`TypeError`/`AttributeError` 与 `ProviderContractError` 不重试。

## 存储、任务与队列

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `FIL_STORAGE_LOCK_TIMEOUT` | `10` | DuckDB 文件锁最长等待秒数；超时抛 `StorageBusy` |
| `FIL_MAX_JOBS` | `2` | 同时运行的分析子进程数 |
| `FIL_QUEUE_LIMIT` | `100` | `queued + running` 任务总上限，超出返回 429 |
| `FIL_JOB_TIMEOUT` | `900` | 单任务超时秒数 |
| `FIL_JOB_ATTEMPTS` | `3` | 进程中断后的最大尝试次数 |
| `FIL_START_DATE` | 未设置 | 固定基金分析起点，覆盖滚动默认值 |
| `FIL_AUTO_SERVICES` | `1` | API 自动拉起 worker；`0` 交由外部进程管理 |
| `FIL_SYNC_ENABLED` / `FIL_SYNC_TIME` | `1` / `18:30` | worker 每日同步开关与北京时间 |
| `FIL_CORS_ORIGINS` | 空 | 逗号分隔跨域来源 |

`StorageBusy` 由 FastAPI 异常处理映射为 **503**（`ok=false`、`field=storage`、可读原因与 `retry_after_s`），表示存储锁暂时被同步或其它进程占用，客户端可稍后重试；`/api/corr` 等路由不会再用通用 500 吞掉它。

端点与字段契约见 [数据源供应商契约](数据源供应商契约.md)。

## 免责声明（P2-36）

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `FIL_DISCLOSURE_SCOPE` | `internal` | `internal` / `external` 两套默认文案 |
| `FIL_DISCLOSURE_TEXT` | 空 | 自定义文案，覆盖默认值 |
| `FIL_DISCLOSURE_POSITION` | `top` | `top`（推荐）或 `footer` |

Web 页顶部横幅与报告首页同时生效；`/api/disclosure` 返回同一份配置。

## 真实数据冒烟与 CI（P2-35）

```bash
python scripts/smoke_real.py --code 110022 --out output/results/smoke
```

手动触发，覆盖抓取→面板→分析→报告；失败时输出目录下的 `smoke_result.json` 会标记
`failure_class = data_source | logic`。CI（`.github/workflows/ci.yml`）只跑
全量单测（366 项，2026-11-06 基线）与 Python/JavaScript 语法检查，不跑真实数据。

## 就绪检查

- `/api/health`：仅存活探针，返回 pid、uptime、`environment`、`access_control`。
- `/api/ready`：检查 DuckDB、worker pid、任务状态分布、估值面板最近同步日期
  （`2×FIL_DATA_STALE_DAYS`）与锁统计；存储/worker/队列异常返回 503，仅同步过期
  返回 200 + `degraded`。
- `/api/disclosure`：返回与 Web/报告一致的免责与数据来源披露，不受访问控制限制。
