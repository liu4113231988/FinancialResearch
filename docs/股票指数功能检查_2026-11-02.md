## 已复现的功能问题

### 1. 市场任务缺少完整的前端控制（P2）

位置：`src/market_research/api/static/market.js:67-102`，示例按钮位于同文件第57行附近。

`submit()` 没有运行中保护，只禁用开始分析、应用区间和刷新按钮。示例卡和证券下拉仍能提交不同证券；第二次提交递增 generation，页面停止跟踪前一任务，但前一后台任务继续占用队列/计算资源。后端相同参数去重不能解决不同证券的重入。

jsdom 实测：首个提交尚未返回时再次调用现有提交入口，产生两次 POST；取消按钮仍隐藏。市场页也没有保存可供取消的任务 ID，轮询没有总时限，透传的 `api()` 没有请求超时或断网重试。服务长期不返回终态时页面可能一直等待，单次请求失败则丢失当前跟踪。

建议：市场页复用已有的任务控制模式，保留当前任务 ID，覆盖所有提交入口，并接上取消、请求超时和有限重试。不能仅靠禁用一个按钮解决。

### 2. 基金自选控件会残留到股票/指数入口（P2）

位置：`src/market_research/api/static/market.js:16`、`src/market_research/api/static/app.js:554`、`:706`、`:1052`。

基金结果完成后 `renderWatchlist()` 显示基金自选控件。切换到股票或指数时，`switchKind()` 不更新这些控件的可见性；自选下拉的 onchange 又无条件调用基金 `run()`。因此在市场入口选择残留的基金自选项会提交基金任务，界面入口与执行内容不符。

jsdom 已复现“基金页渲染自选 → 切回股票 → 自选下拉仍可见”。默认股票页先隐藏自选控件的路径不能证明后续切换正确。

建议：每次入口切换时统一刷新自选控件状态，并在自选回调检查资产类型。

### 3. 价格图均线与技术信号的预热口径不一致（P2）

位置：`src/market_research/market/analysis.py:159-185`、`:228-232`，前端 `market.js:118-127`。

技术区块使用同步历史预热，价格图和概览的 MA20/60/120 却只用展示区间计算。相同证券、日期和复权方式下，短区间会出现价格图均线缺失，但技术区块依赖同一均线给出趋势判断的现象；布林带也可能已显示而其对应的 MA20 仍为空。

合成行情实测：提供420根一致历史，展示最后30根，价格图末日 MA60 和概览 MA60 偏离均为 null；技术区块 MA60 为139.117296，`ready=true`。展示首日 MA20 为空，但布林上轨非空。

建议：均线和技术信号使用同一份已核对复权一致性的历史预热，再截取展示区间；区间收益继续按用户选定起止日计算。

## 功能覆盖与剩余缺口

| 能力 | 核对结果 |
| --- | --- |
| 股票/指数代码校验与独立入口 | 已实现；股票限沪深京A股，指数入口限 sh000xxx / sz399xxx，并非全部指数 |
| 日线、复权、成交量、收益风险、基准比较 | 已实现；股票有主备行情源，指数采用新浪行情 |
| 技术指标、环境特征、5/20会话方向估计 | 已实现；无完整日历时降级为有效日线周期，历史不足时不输出模型预测 |
| 冷启动方向估计 | 默认一年展示历史不足以覆盖252个成熟训练样本及指标预热；依赖先完成同步或选择更长区间，页面不会主动补齐训练历史 |
| 成交与资金验证 | 页面有固定费用的可分割成交诊断；整手、最低佣金和容量等资金情景主要在离线入口 |
| 概率校准 | 离线已有训练/校准/留出分隔；页面仍输出未单独校准的模型概率 |
| 个股基本面与行业比较 | 财报、公告、完整估值历史、个股相对行业、历史行业归属仍不完整 |
| 指数成分与市场宽度 | 尚无历史时点成分驱动的涨跌家数、均线上方比例、新高新低等分析 |
| 实际交易有效性 | 尚缺充分的未来独立样本、真实ETF成交/跟踪偏差、公司行动及完整历史成交限制验证 |

日历质量还有一项边界：`market_quality()` 只统计实际首末报价之间的缺日。即使请求末端缺了5个已知会话，缺日计数也可能为0，只有请求/实际日期和自然日差距体现截断。本次复现 `calendar_verified=true`、两个缺日计数为0、末端相差7个自然日。这符合当前“区间内部缺日”的定义，但不能把该字段当成整个请求区间完整覆盖的证明；可增加独立的末端未覆盖会话提示，不必把原因直接判为停牌或数据过期。
